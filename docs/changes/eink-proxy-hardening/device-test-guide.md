## 一、环境准备

### 1.1 获取测试构建（二选一）

- **路径 A（推荐，真机连 Windows 测试机）**：在你的 Windows 开发机上
  `flutter build apk --release`，或从项目 CI（GitHub Actions）下载本次改动的
  APK，安装到真机。
- **路径 B（真机连本机 Linux）**：本机 `~/flutter` 已就绪，但暂无 Android
  SDK；如需在本机出包，先安装 Android cmdline-tools 并
  `flutter doctor --android-licenses` 后 `flutter build apk --release`。

### 1.2 测试代理

- 局域网代理：`http://192.168.2.153:16492`（已验证可用，GitHub API 200）。
- 真机与本机/代理须在同一局域网。
- 若你的代理端（clash 等）有连接日志，测试时打开它，作为「代理端观察」回执。

### 1.3 取证方式（回执证据）

1. **应用内日志**：设置 → 日志 → 复制/导出。关注 `[network]` 开头的行，
   格式：`[network] GET <url> -> <状态码>`（成功，仅部分路径记录）或
   `[network] GET <url> failed: <原因>`（失败必记）。
2. **截图**：设置页「网络」入口、外观页「E-Ink 模式」区块、E-Ink 阅读效果。
3. **代理端观察**：代理日志中是否出现真机 IP 的请求记录。

## 五、已知限制（测试时注意）

1. 「跟随系统」档在 Android 上读取的是环境变量代理（桌面端有效），
   Android 无标准全局代理 API，通常表现为直连——这是预期行为，
   请用「自定义代理」档做代理验证（T1-T6）。
2. E-Ink 切章闪烁只是视觉提示/大面积纯色变化，能否触发设备驱动的
   全局刷新取决于各厂商固件（BOOX/汉王等行为不同），E3 请描述实际观感。
3. T4 热更新测试中，图片加载有磁盘缓存，请翻**未读过的页**。
