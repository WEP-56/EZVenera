# Requirements Specification — E-Ink 适配、网络代理与稳健性加固

## Problem

1. E-Ink 屏幕刷新慢、有残影，当前阅读器的动画（翻页/缩放/淡入淡出）和
   Material 3 低对比度主题在 E-Ink 上产生闪屏与可读性问题。
2. 用户无法配置代理，导致在受限网络下无法访问图源、图片、更新与 WebDAV。
3. 网络出口分散（多处裸 `Dio(`），配置无法统一刷新；多处存在静默失败、
   无重试、无校验的路径，稳健性不足。

## Users / Actors

- 读者（Android / Windows 用户，含 E-Ink Android 设备用户）
- 受限网络用户（需代理访问图源/更新/WebDAV）
- 维护者（需要可复现的诊断日志与验证路径）

## Scope

### In scope

- E-Ink 模式设置（外观区）+ 阅读器行为切换（禁用动画、高对比度主题）
- 代理设置（网络区）：系统代理 / 自定义代理 / 无代理三态，覆盖全部网络出口
- 网络层统一出口（Dio 工厂 + 运行时可刷新配置）
- 选定的稳健性加固（配置原子写、图片解码降级、下载重试、日志结构化）
- Rust 性能评估（基准 + 结论，不承诺迁移）

### Out of scope

- 新增漫画源/插件能力（项目 README 明确不接受"对插件运行时功能增加"）
- iOS/桌面 Linux 平台适配（项目范围为 Windows + Android）
- 对既有插件 JS API 的任何修改
- 全量 Rust 重写（仅评估热点迁移）
- 代理的认证（用户名/密码）持久化 — 首版仅支持匿名/透明代理与系统代理

## Non-Functional Requirements

| ID | Category | Requirement | Measurement |
|---|---|---|---|
| NFR-001 | 性能 | E-Ink 模式阅读器翻页响应不因禁用动画而变差 | 翻页回调到帧渲染耗时 < 100ms 无动画 |
| NFR-002 | 安全 | 代理配置不持久化密码；日志不记录代理认证信息 | 静态检查无明文存储 |
| NFR-003 | 兼容 | 旧版 `app_settings.json` 可无损加载（新键缺省即有默认值） | 用 v1.8.7 的备份文件启动测试 |
| NFR-004 | 可维护 | 新增代码通过 `flutter analyze` 无新告警 | `flutter analyze` 退出码 0（相对基线） |
| NFR-005 | 回归 | 既有功能（搜索/阅读/下载/备份）无行为回归 | `flutter test` 全过 + 手动冒烟 |

## Constraints

- E-Ink 真机（如 BOOX、Kindle 系 Android 设备）不在本机，需用户实测。
- rhttp 固定版本 `0.15.1`（pubspec 注释明确与 `flutter_rust_bridge 2.11.1`
  配对），代理 API 需适配该版本的 `ProxySettings`。
- 不做 iOS；Windows + Android 双平台。
- 不修改插件 JS API / `assets/init.js` 契约。

## Assumptions

- 目标 E-Ink 设备为 Android（最小 API 版本沿用现有配置）。
- 首版代理仅需要 HTTP(S) 代理（socks 暂不做）。
- 用户代理场景以「HTTP 代理 + 无认证」为主，认证代理列入后续。

## Open Questions

- OQ-001：E-Ink 模式是否自动检测设备（通过屏幕密度/厂商）还是纯手动开关？
  — 建议首版手动开关；自动检测列为后续（需调研 E-Ink 厂商指纹）。
- OQ-002：全屏刷新提示的触发频度（每页/每 N 页/章节切换）？
  — 建议首版每章节切换 + 可选每页。
- OQ-003：socks 代理是否进入首版？— 默认否。
